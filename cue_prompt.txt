You classify concerns that an AI agent wrote about database records it retrieved. For each concern, mark every cue the concern actually uses to justify its doubt. Judge the text as written.

## The cues
c, cross-field: the data the agent got from the database contradict each other. One field disagrees with another field of the
  same record (protein: mass vs length, protein name vs gene symbol, organism vs subcellular location; chemistry: molecular
  weight vs heavy-atom count vs hydrogen-bond donors, e.g. "too many daltons per heavy atom", "more donors than atoms"), or a
  second lookup in the same tool (e.g. by name or gene) returned a different record or none.
r, recall: the agent relies on its own knowledge of this specific protein or compound: its known length, mass, gene, organism or
  identity; its formula, structure or functional groups as the agent states them; what it "actually" is; literature, textbook,
  typical or expected values ("the known ~223 aa", "aspirin is C9H8O4", "it has two hydroxyl groups", "should be about 180 Da").
u, rule: a general rule that holds for any protein or compound, with no reference to another field and no knowledge of this
  entity: a length, mass or count cannot be zero or negative; nothing weighs less than a hydrogen atom; no protein or molecule is
  that large; every compound has at least one heavy atom; the name is not a valid gene or chemical name; the value looks like a
  placeholder or missing value.
n, none: doubt without any of these grounds ("seems unusual", "could not verify", "may be a data error").

Combine letters when several apply (e.g. "cr"). Use n only alone.

## Edge cases
1. Comparison target. "The mass is inconsistent with the length" -> c. "The mass is inconsistent with the known length of ~300 aa"
   -> r (the comparison is with memory). If both the record's own field and a remembered value are cited -> cr.
2. Identity. "The record's protein name is UNC5D but the gene symbol is XBP1" -> c. If the concern adds outside knowledge
   ("XBP1 encodes X-box-binding protein 1, P17861") -> also r.
3. Formula and structure. A formula described as the record's ("the stated/listed formula") -> c. A formula, structure or
   functional group the agent asserts on its own -> r.
4. Several grounds. "0 Da is impossible; the known mass is ~45 kDa" -> ur.
5. A second lookup that merely repeats the same data is not a contradiction; tick c only if the results disagree.


## Deciding difficult cases
- Mark a cue only for the reason the concern gives. Words such as "impossible", "implausible", "erroneous" or "unusually high"
  are not a cue by themselves; ask what the value is judged against.
- crossfield needs two pieces of database data set against each other: one field of the record against another field, or a
  second lookup. An expected value the concern computes from another field of the record (about 110 Da per residue times the
  record's length; a weight that fits the record's heavy-atom count) is crossfield. In chemistry, a value judged against the
  record's own weight, heavy-atom count or donor count ("for a 15-heavy-atom molecule", "(MW 247, 18 heavy atoms)") is crossfield,
  even if the compound is also named.
- Mentioning several record fields while comparing them with remembered or "canonical" values is recall only, not crossfield.
  Using a record field to recognise the entity from memory ("the length matches the human protein") is recall only.
- recall needs a stated fact about this particular protein or compound that is not in the record: its known or canonical value,
  what the accession or gene really is, what a compound with this name is or should contain. Merely naming the entity is not recall.
- Gene symbols: a gene symbol set against the protein name quoted from the record -> crossfield and also recall (recognising that
  the gene does not encode that protein needs knowledge). If the concern states what the accession is without referring to the
  record's protein name -> recall only.
- rule only when the stated reason is a constraint for any protein or compound: cannot be zero or negative, lighter than a hydrogen
  atom, larger than any molecule, not a valid name, a placeholder. A zero or negative value called invalid on its own -> rule.
  If the concern says the value is impossible given another field -> crossfield, not rule.

You will receive several numbered concerns; classify each independently. Answer with only a JSON array with one object per
concern, in the same order: [{"crossfield": true or false, "recall": true or false, "rule": true or false}, ...]
