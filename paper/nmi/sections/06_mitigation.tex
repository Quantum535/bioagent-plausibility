\subsection*{A second source catches what derivation checks cannot}
A harness that checks each record against its own derivations before the agent sees it (Methods) removed constructed single-field
errors almost entirely: relay fell to 0--1\% for proteins with Opus~5, Argon and DeepSeek. In chemistry 12--24\% remained,
concentrated in compound names, which have no derivation route.
% src: Phase 2 harness (results/harness); Phase 2 replace rerun (results/coherent/RESULTS.md, methods note b)

Coherent and real errors pass derivation checks by construction, so we added an independent second source: AlphaFold~DB for
proteins, whose sequences matched UniProt for all 299 proteins it covers, and NCI~CACTUS for chemistry, which agreed with PubChem's
formula for 270 of the 283 compounds it resolved (Methods). Neither raised a false alarm in 1,200 checks of clean fields. Where the
second source covered the entity, it caught most coherent errors: Argon relayed none, Opus relayed 4 of 49 lengthened proteins and
nothing else, and DeepSeek relayed 9 of 49 lengthened proteins and a few others. On the real UniProt errors, relay of covered proteins over three samples was 9\% (Opus, 21/234), 1\% (Argon, 2/233) and 33\% (DeepSeek, 77/234), each model's rate stable across samples (DeepSeek 31--36\%). Where the second source did not cover the
entity, errors passed in 26 of 30 runs, and the one uncovered real error passed for every model and record format.
% src: results/coherent/RESULTS.md (finding 4); results/phase5/RESULTS.md (R2); results/robustness/RESULTS.md (Part 2)

What remained followed a pattern we found in the constructed errors and then registered for the real ones: agents deferred to the
database when its record was longer than the second source's. Residual relay was higher for superseded records longer than today's than for shorter ones: 25\% against 11\% in the first sample (one-sided Fisher $p = 0.007$) and 23\% against 11\% pooled over three samples (44/189 against 56/512), with the same direction in every sample ($p = 0.007$, $0.044$ and $0.116$). Agents reported
both values and answered with the record's (``1111 aa (record) / 889 aa (AlphaFold)''); in the first sample DeepSeek flagged the discrepancy in 24 of its 25 relayed runs. A harness message reporting that all fields were consistent did not make agents more trusting of a coherent error (Methods).
% src: results/phase5/RESULTS.md (R3); results/robustness/RESULTS.md (R3 per sample); results/coherent/RESULTS.md (finding 5)

\subsection*{Correcting the record works; showing the conflict does not}
If agents defer to the record, the remedy is to correct the record. We compared three ways of presenting a correction from the
second source on the real errors, with three samples per run and predictions registered in advance (Fig.~\ref{fig:presentation}).
Writing the corrected value into the record while listing the original in a verification note with ambiguous field names left
3--11\% relay. Labelling the original explicitly as the original database value made one model markedly worse: Argon chose it in
41\% of runs (``Based on the original UniProt database value for protein O00154 ...''). Correcting the record silently, with no
note, removed relay entirely: 0 of 702 runs across the three models.
% src: results/robustness/RESULTS.md (Parts 1 and 3)

When the conflict was shown, Opus and DeepSeek mostly resolved it from memory, citing a recalled ``canonical'' length that matched
the superseded entry (10 of 12 and 14 of 17 relayed runs with the labelled note, by a text match), while Argon deferred to the
labelled original. No model restored a value from memory when no conflict was shown: memory acted as a tie-breaker once a
disagreement was visible, not as an independent check. Silent correction is only as safe as the second source. AlphaFold~DB
matched current UniProt for every protein it covers, so silent replacement never altered a clean record here; a source that
disagreed with the primary database as often as NCI~CACTUS does (about 5\%) would insert errors into clean records.
