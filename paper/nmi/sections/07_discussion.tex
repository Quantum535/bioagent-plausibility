\section*{Discussion}

In every setting we tested, the variable that decided whether a wrong value reached the answer was whether the record contradicted it. A record that agreed with itself carried an error of any size from the summary record, a three-residue protein as readily as a revision of a few residues, with or without the entity's identity and with or without a request to list concerns. A contradiction made override possible. Whether it happened then depended on the size of the contradiction, on the model and on what the model knew: Argon acted on a sequence alone, Opus~5 mainly on its knowledge of the protein, and DeepSeek rarely. Plausibility mattered at the extremes, where a mass of 0~Da read as a placeholder, but within the range of values that look like data it did not decide.

Two findings qualify the picture of agents that notice errors and relay them anyway. First, much of the noticing of plausible errors was elicited: asked to list concerns, agents flagged them; unprompted, they rarely did, and relayed more. Benchmarks that solicit concerns therefore overstate how often agents notice errors and understate how often they relay them. Second, agreement is not repetition. A derived field that agreed with a wrong value strengthened it, a field that disagreed removed it, and a verbatim agreeing copy under a familiar name added nothing. The agents responded to contradiction, not to the number of times a value appeared.

These results extend work on knowledge conflicts, in which models adopt incorrect context even against their memory \citep{xu2024conflicts,wu2024clasheval,xie2024adaptive}, and concurrent work showing that tool-using agents question a corrupted return while passing it on \citep{yang2026overreliance}. A structured record adds what text lacks: fields that can contradict one another. That structure is what the agents used, and it is what real errors lack, because a database revision replaces a sequence together with everything derived from it.

Three implications follow for systems that put agents on scientific databases. First, instructions help only where a contradiction exists, and output formats only where the model's memory is right. Neither reaches an error that is consistent with its record and absent from, or wrong in, the model's memory. Second, the reliable remedies act on the record before the agent reads it. Withholding fields that fail a derivation check, or correcting silently from a current copy, left nothing to relay without lowering accuracy, whereas showing the agent both values reopened the decision and let memory or a label settle it. The design principle is to resolve conflicts before the model sees them and to keep the audit trail for the people responsible for the analysis. Third, a second copy is only as good as its currency and coverage: AlphaFold DB caught superseded UniProt sequences because it mirrors the current release, a lagging mirror would carry the same error, and entities outside its coverage remain blind spots.

The study has limits. Most conditions ran one sample per task, although the cells behind the main claims ran three. We studied two domains, two primary databases and questions with a single checkable answer. Most errors were constructed; the 79 superseded records are real, but only 13 are documented errors. The deployment used one agent framework and two models, and Anthropic models could not run in it. Behaviour is tied to the 2026 model versions tested, which were requested by alias, and reasoning settings, which we varied for three models, changed override clearly for one of them (Opus 5). Several experiments were designed after earlier results and registered before they ran.

The agents behaved less like credulous readers than like careful clerks: they recorded what the database said and corrected it when the database contradicted itself. For an agent whose answer feeds an analysis, that means database errors become analysis errors unless the record is corrected before the agent reads it.
